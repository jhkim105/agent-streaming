# 기능 명세서: 핵심 에이전트 스트리밍 및 AGUI 프로토콜 시스템

**기능 식별자**: `specs/001-core-agent-streaming`  
**대상 도메인**: 대화형 AI 에이전트, 실시간 SSE 스트리밍, AGUI / A2UI 인터랙티브 UX  
**진행 상태**: DRAFT (초안 작성 완료)  

---

## 🎯 1. 사용자 가치 및 비즈니스 목표

### 개요
대화형 AI 시스템에서 사용자가 질문을 입력했을 때, 단순한 텍스트 답변만을 지루하게 기다리는 대신 **에이전트의 실시간 사고 과정(Thinking Steps)**을 투명하게 관찰하고, **실시간으로 타이핑되는 마크다운 결과물**과 함께 **선언적 AGUI/A2UI 인터랙티브 대시보드(핵심 지표 카드 및 추천 후속 액션 버튼)**를 즉각 제공받아 풍부하고 연속적인 대화 경험을 누릴 수 있도록 합니다.

---

## 👤 2. 사용자 시나리오 및 여정 (User Journey)

### 페르소나: AI 어시스턴트를 활용하는 지식 작업자 (연구원 / 개발자 / 기획자)
- **주요 목표**: 복잡한 질문에 대해 에이전트가 어떤 단계로 탐색 중인지 실시간으로 파악하고, 결과와 함께 제공되는 대화형 UI 컴포넌트를 통해 키보드 입력 없이도 손쉽게 후속 탐색을 이어간다.

### 사용자 여정 흐름
1. **대화 시작**: 사용자가 `[+ 새 채팅]` 버튼을 누르거나 좌측 사이드바에서 이전 대화 목록을 선택합니다.
2. **질문 전송**: 질문을 입력하고 전송하면 입력창은 즉시 전송 완료 상태가 되고 우측 말풍선에 표시됩니다.
3. **사고과정 관찰 (투명성)**: 좌측 영역에 에이전트의 내부 사고과정(Thinking Accordion)이 실시간으로 누적 표출됩니다.
4. **결과 수신 (스트리밍)**: 생성된 마크다운 텍스트가 타자기 효과로 실시간 스트리밍됩니다.
5. **AGUI 인터랙션**: 스트림 완료와 함께 AGUI 프로토콜 기반의 핵심 지표 카드와 추천 후속 액션 버튼이 인라인 렌더링됩니다.
6. **후속 행동 (Human-in-the-Loop)**: 사용자가 후속 액션 버튼을 클릭하면 추가 질문 타이핑 없이도 동일 스레드에서 연관 탐색이 즉시 이어집니다.

## 📋 3. 기능적 요구사항 (Functional Requirements)

### FR-1: 대화 스레드 및 세션 라이프사이클 관리
- **FR-1.1**: 사용자는 명시적으로 새로운 대화 스레드(`conversationId`)를 시작할 수 있어야 한다.
- **FR-1.2**: 사용자는 좌측 사이드바에서 이전 대화 목록을 언제든지 조회할 수 있어야 하며, 최신 대화 순으로 정렬되어야 한다.
- **FR-1.3**: 사용자가 목록에서 특정 이전 대화를 선택하면 해당 대화의 과거 질문-답변 내역, 사고과정 타임라인, AGUI 대시보드 상태를 정확히 조회/복원해야 한다.
- **FR-1.4**: 복원된 이전 대화 상태에서 사용자가 새로운 질문을 입력하면, 기존 대화 맥락(Context)을 그대로 유지한 채 멀티턴 대화를 자연스럽게 이어나갈 수 있어야 한다.

### FR-2: 실시간 단방향 스트리밍 (SSE)
- **FR-2.1**: 클라이언트는 대화 스레드 접속 시 실시간 단방향 SSE 연결을 수립하고 고유 연결 식별자(`connectionId`)를 발급받아야 한다.
- **FR-2.2**: 사용자가 질문을 전송하면 백엔드는 작업을 비동기로 큐잉하고 접수 완료(`202 Accepted`) 응답을 즉시 반환해야 한다.
- **FR-2.3**: 스트림을 통해 상태 알림(`STATUS`), 텍스트 조각(`CHUNK`), AGUI UI 스키마(`A2UI_RENDER`), 완결(`DONE`), 에러(`ERROR`) 이벤트를 실시간으로 순차 전달해야 한다.

### FR-3: 에이전트 사고과정(Thinking Accordion) 시각화
- **FR-3.1**: 에이전트가 탐색하거나 추론 중인 진행 단계(`STATUS`)를 접기/펴기가 가능한 독립된 아코디언 UI로 표출해야 한다.
- **FR-3.2**: 스트리밍이 진행 중일 때는 스피너 또는 로딩 인디케이터로 진행 중임을 알리고, 완료 시 완료 상태로 전환해야 한다.

### FR-4: AGUI / A2UI 선언적 인터랙티브 컴포넌트 렌더링
- **FR-4.1**: 시스템은 에이전트가 반환한 AGUI 프로토콜 기반의 선언적 JSON 스키마를 파싱하여 인라인 대시보드로 렌더링해야 한다.
- **FR-4.2**: AGUI 대시보드는 핵심 지표 수치 카드(Metrics)와 에이전트 추천 후속 행동(Action Section)을 포함해야 한다.
- **FR-4.3**: 사용자가 AGUI 액션 옵션 버튼을 클릭하면 즉시 해당 페이로드를 담은 에이전트 턴 실행 요청(Run Request)이 전송되어 대화 맥락이 단절 없이 이어져야 한다.

## ⚡ 4. 성공 기준 (Success Criteria)

1. **사용자 체감 지연시간 (Perceived Latency)**: 사용자가 질문 제출 후 1초 이내에 첫 번째 에이전트 사고과정(`STATUS`) 또는 초기 응답 신호가 화면에 표출되어야 한다.
2. **연속 인터랙션 편의성**: AGUI 추천 액션 버튼 클릭 시 별도 타이핑 없이 즉시 100% 후속 질의 스레드로 연계되어야 한다.
3. **상태 복원 무결성**: 이전 대화 목록에서 과거 대화를 선택했을 때 텍스트뿐만 아니라 과거 AGUI 대시보드와 사고과정 타임라인이 원본 상태 그대로 복원되어야 한다.
4. **스트리밍 무유실성**: 네트워크 정상 환경에서 발행된 모든 마크다운 텍스트 토큰과 UI 스키마가 순서 뒤바뀜 없이 클라이언트에 정확히 전달되어야 한다.

---

## 📌 5. 가정 및 제약사항 (Assumptions & Constraints)

- **AGUI 표준 프로토콜**: 클라이언트와 에이전트 간의 UI 메시지 교환은 선언적 JSON 규격(`A2UI Schema v1.0`)을 준수한다.
- **비동기 파이프라인**: AI 연산은 메인 웹 서버 스레드를 블로킹하지 않고 완전 비동기 이벤트 버스로 처리된다.
