# Real-time AI Researcher Agent - Requirements (요구사항 정의서)

이 문서는 실시간 AI 리서처 에이전트(Real-time AI Researcher Agent) 시스템의 핵심 기능적 및 비기능적 요구사항을 기술합니다.

관련 문서: [시스템 아키텍처](2.architecture.md) | [기술 명세서](3.spec.md) | [구현 계획서](4.plan.md) | [기술 문서](../tech/0001-multi-node-session-routing-test-guide.md)

## 1. 프로젝트 개요

사용자가 입력한 리서치 질문에 대해 AI 에이전트가 실시간 웹 탐구 및 자연어 추론을 수행하고, 사용자는 대기 지연 없이 실시간으로 에이전트의 상태 및 생성되는 마크다운 보고서를 확인받는 이벤트 구동형 스트리밍 시스템을 구축합니다.

본 시스템은 **비동기 스트리밍 연결 관리를 담당하는 앞단 서버**와 **AI 다단계 추론을 수행하는 파이썬 에이전트 워커**를 비동기 이벤트 브로커 및 인메모리 캐시로 연결하여, 높인 확장성과 결합도 격리를 증명하는 것을 목표로 합니다.

---

## 2. 사용자 시나리오 (User Journey)

1. **서비스 접속 & 세션 연결**: 사용자가 웹 UI에 접속하면 스트리밍 서버와 실시간 세션이 자동 수립되어 유니크한 세션 식별자를 할당받습니다.
2. **질문 제출**: 사용자가 채팅 입력 창을 통해 리서치 질문을 등록합니다. (예: *"LiteLLM 프레임워크 최신 기능 조사해줘"*)
3. **진행 상태 실시간 수신**: UI에 에이전트의 내부 추론 및 탐구 단계가 시각적 타임라인 형태로 실시간 표시됩니다.
4. **리포트 스트리밍 렌더링**: 에이전트가 작성해 나가는 분석 보고서 마크다운 텍스트를 실시간 타자기 효과(Token Streaming)로 수신받아 확인합니다.
5. **완료 및 예외 처리**: 리포트 작성이 완료되면 완료 신호를 수신하고, 예외 발생 시 안전하게 에러 안내를 전달받습니다.

## 3. 기능적 요구사항 (Functional Requirements)

### 3.1. 실시간 세션 및 스트리밍 관리
* **연결 유지 및 세션 분리**: 클라이언트와의 실시간 연결을 지속 유지하고 세션별 독립성을 보장하여, 에이전트의 작업 상태 및 답변 텍스트를 실시간 단방향 스트리밍으로 지연 없이 전달해야 한다.
* **비동기 요청 처리 및 격리**: 사용자의 질문 요청을 백엔드 메시지 브로커로 즉시 전환하여, HTTP 대기 커넥션과 백그라운드 AI 에이전트 작업을 완벽히 비동기로 분리해야 한다.
* **분산 세션 라우팅**: 다중 서버 환경(Scale-out)으로 인스턴스가 증설되더라도 사용자의 세션 소켓을 보유한 타깃 서버 노드로 이벤트를 유실 없이 정확히 전달해야 한다.

### 3.2. AI 에이전트 워크플로우 및 자연어 추론
* **다단계 추론 및 실시간 정보 탐구**: 사용자의 질의 의도를 분석하고 pure 검색어를 추출하여, 최신 웹 정보 조회 및 본문 텍스트 수집을 순차적으로 수행해야 한다.
* **로컬 대형 언어 모델(LLM) 연동 스트리밍**: 수집된 실시간 자료를 바탕으로 로컬 LLM 신경망이 깊이 있는 자연어 마크다운 분석 리포트를 토큰 단위로 실시간 생성해야 한다.
* **구조화된 이벤트 유형 제공**: 클라이언트가 시각적으로 구분할 수 있도록 작업 진행 상태(STATUS), 텍스트 조각(CHUNK), 대시보드 컴포넌트(A2UI), 완료 신호(DONE) 이벤트를 표준화하여 전송해야 한다.

### 3.3. 프론트엔드 사용자 경험 (UI/UX)
* **독립된 웹 사용자 인터페이스**: 사용자가 직관적으로 질문을 입력하고 결과를 확인할 수 있는 전용 웹 UI를 제공해야 한다.
* **실시간 작업 타임라인 시각화**: 에이전트의 현재 추론 단계(질문 분석 ➔ 웹 검색 ➔ 본문 스크래핑 ➔ LLM 추론)를 타임라인 카드로 표시해야 한다.
* **마크다운 타자기 효과 렌더링**: 수신되는 마크다운 청크 텍스트를 실시간으로 파싱하여 자연스러운 타자기 효과로 렌더링해야 한다.

## 4. 비기능적 요구사항 (Non-Functional Requirements)

### 4.1. 응답성 및 스트리밍 품질
* **빠른 초기 피드백 제공**: 사용자가 질문을 전송한 후 첫 번째 에이전트 작업 상태가 화면에 보이기까지의 대기 시간을 최소화해야 한다.
* **매끄러운 스트리밍**: 미들웨어 및 라우팅 릴레이 과정에서 병목 없이 부드러운 토큰 스트리밍 출력을 유지해야 한다.

### 4.2. 확장성 및 예외 복원력 (Scalability & Resilience)
* **수평 확장 보장 (Scale-out)**: 스트리밍 서버 인스턴스를 무한히 증설하더라도 사용자 세션 라우팅이 어긋나지 않고 보장되어야 한다.
* **에이전트 장애 격리**: 파이썬 에이전트나 LLM 서비스에 예외나 지연이 발생하더라도 앞단 스트리밍 서버 및 사용자 커넥션이 보호되며 에러 안내를 안전하게 전송할 수 있어야 한다.
