## 1. 아키텍처 개요 및 도메인 모델 분리

본 시스템은 동시 연결 처리가 우수한 **JVM 리액티브 모델(Kotlin WebFlux Agent Stream Server)**과 **파이썬 에이전트 워커(LangGraph Worker)**를 비동기 메시지 브로커(Kafka), 노드별 레디스 스트림(Redis Streams `stream:host:{hostId}`) 및 대화 영속성 저장소로 연결한 **0% 유실 무중단 이벤트 구동형 대화 아키텍처**입니다.

### 🔑 식별자 및 아키텍처 구조 (Identity & Dynamic Routing Model)
* **`sessionId` (Stream Connection ID)**: 네트워크 SSE 연결 생명주기를 다루는 소켓 식별자입니다. 새로고침 시 새로 생성됩니다.
* **`conversationId` (Business Conversation ID)**: 리서치 대화 스레드의 생명주기를 다루는 도메인 식별자입니다. 새로고침하더라도 동일한 대화 이력 및 리포트를 복원합니다.
* **`hostId` (Server Instance ID)**: 코틀린 스트리밍 서버 노드의 유니크 식별자입니다 (예: `kotlin-node-1`).
* **Redis Session Registry (`session:host:{sessionId}`)**: SSE 연결 시점에 소켓 위치를 등록하여, L4/L7 라운드로빈으로 질문이 다른 노드로 유입되어도 응답 수신 시점(Consumer)에 실재 소켓 노드를 동적 추적하여 무중단 배달합니다.
* **Node-based Redis Stream (`stream:host:{hostId}`)**: 각 서버 노드가 본인 이름의 레디스 스트림 단 1개만 `XREAD`로 지속 수신하여, **노드당 Redis 커넥션 수 상한을 정확히 1개로 고정**합니다.

## 3. 시퀀스 플로우 (Sequence Diagram)

### 3.1. 대화 수립, 세션 위치 등록 및 동적 라우팅 플로우

```mermaid
sequenceDiagram
    autonumber
    actor Client as Client (React SPA)
    participant Server1 as Stream Server (node-1)
    participant Server2 as Stream Server (node-2)
    participant RedisReg as Redis Session Registry
    participant Kafka as Kafka Broker
    participant Agent as Python Worker (Qwen2.5)
    participant RStream as Redis Streams (stream:host:node-1)

    %% 1. SSE Connection & Session Location Registry
    Client->>Server1: GET /api/chat/stream?conversationId=conv-100
    Note over Server1: sessionId 생성 (sse-100)<br/>conversationId 바인딩 (conv-100)
    Server1->>RedisReg: SET session:host:sse-100 "node-1" EX 3600
    Server1-->>Client: event: INIT (sessionId: "sse-100", conversationId: "conv-100")

    %% 2. L4 Round-Robin POST Request
    Client->>Server2: POST /api/chat/message (conversationId: "conv-100", sessionId: "sse-100", query: "LiteLLM")
    Server2-->>Client: 202 Accepted
    Server2->>Kafka: Produce to 'agent-requests' (hostId 미고정 발송)

    %% 3. Python Worker Processing
    Kafka->>Agent: Consume request
    loop Web Search & Ollama LLM Streaming
        Agent->>Kafka: Produce response (STATUS / CHUNK / A2UI / DONE)
    end

    %% 4. Consumer Dynamic Lookup & Redis Streams Relay
    Kafka->>Server2: Consume response (type: CHUNK / STATUS / A2UI)
    Server2->>RedisReg: GET session:host:sse-100 동적 조회
    RedisReg-->>Server2: "node-1" (Node 1에 소켓 존재 확인!)
    Server2->>RStream: XADD stream:host:node-1 (targetHost: node-1, event: CHUNK)

    %% 5. Node 1 Stream Read & Client SSE Delivery
    RStream->>Server1: XREAD stream:host:node-1 (Node 1 전용 스트림 수신)
    Server1-->>Client: event: CHUNK / STATUS / A2UI (SSE 배달)
```

### 3.2. 새로고침 시 W3C `Last-Event-ID` 복원 및 대화 이력 조회 플로우

```mermaid
sequenceDiagram
    autonumber
    actor Client as Client (React SPA)
    participant Server as Stream Server
    participant RStream as Redis Streams (stream:host:node-1)
    participant Store as Conversation History Store

    %% 1. 새로고침 발생 시 Last-Event-ID 커서 복원
    Note over Client: 사용자가 브라우저 새로고침 발생!
    Client->>Server: GET /api/chat/stream?conversationId=conv-100 (Header: Last-Event-ID: 17861870-0)
    Server->>RStream: XREAD stream:host:node-1 (Last-Event-ID 이후 미열람 토큰 조회)
    RStream-->>Server: 미열람 CHUNK / STATUS 이벤트 반환
    Server-->>Client: event: CHUNK / STATUS (끊긴 시점부터 무유실 복원 스트리밍!)

    %% 2. 이전 대화 상세 및 완료 리포트 조회
    Client->>Server: GET /api/chat/conversations/conv-100
    Server->>Store: conversationId('conv-100') 이력 조회
    Store-->>Server: 대화 요약, 타임라인, 완성된 마크다운 보고서, A2UI JSON 반환
    Server-->>Client: 200 OK (이전 대화 화면 완벽 복원)
```

## 4. 핵심 데이터 구조 및 REST API 명세

### 4.1. Redis 데이터 키 구조
1. **`session:host:{sessionId}` (Key-Value)**: `kotlin-node-1` (소켓 보유 노드 ID, TTL 3600초)
2. **`stream:host:{hostId}` (Redis Streams)**: 노드별 전용 무유실 레디스 스트림

### 4.2. REST API 사양
* **`GET /api/chat/stream?conversationId={id}`**: SSE 스트림 커넥션 수립 (W3C `Last-Event-ID` 수신 시 미열람 토큰 리플레이 스트리밍)
* **`POST /api/chat/message`**: 질의 전송 (`conversationId`, `sessionId`, `query` 발송)
* **`POST /api/chat/action`**: A2UI 사용자 선택 액션 버튼 제출
* **`GET /api/chat/conversations`**: 이전 대화 목록 요약 조회
* **`GET /api/chat/conversations/{conversationId}`**: 특정 대화 상세 이력 및 완료 리포트 복원 조회
