## 1. 아키텍처 개요 및 도메인 모델 분리

본 시스템은 동시 연결 처리가 우수한 **JVM 리액티브 모델(Kotlin WebFlux Agent Stream Server)**과 **파이썬 에이전트 워커(LangGraph Worker)**를 비동기 메시지 브로커(Kafka), 레디스 버킷 스트림(Redis Streams `stream:bucket:{00~15}`) 및 대화 영속성 저장소로 연결한 **무유실 이벤트 구동형 대화 아키텍처**입니다.

### 🔑 식별자 및 아키텍처 구조 (Identity & Bucketing Model)
* **`sessionId` (Stream Connection ID)**: 네트워크 SSE 연결 생명주기를 다루는 소켓 식별자입니다. 새로고침 시 새로 생성됩니다.
* **`conversationId` (Business Conversation ID)**: 리서치 대화 스레드의 생명주기를 다루는 도메인 식별자입니다.
* **Stream Bucketing (`stream:bucket:{00~15}`)**: `conversationId`를 16개 버킷으로 해시 분할하여 동시 대화방 수에 상관없이 Redis XREAD 커넥션 수 상한을 16개 이하로 통제합니다.

## 3. 시퀀스 플로우 (Sequence Diagram)

### 3.1. 대화 수립, 세션 위치 등록 및 동적 라우팅 플로우

```mermaid
sequenceDiagram
    autonumber
    actor Client as Client (React SPA)
    participant Server1 as Stream Server (node-1)
    participant Server2 as Stream Server (node-2)
    participant RedisReg as Redis Session Registry
    participant Kafka as Kafka Broker
    participant Agent as Python Worker (Qwen2.5)
    participant RStream as Redis Streams (stream:bucket:07)

    %% 1. SSE Connection & Session Location Registry
    Client->>Server1: GET /api/chat/stream?conversationId=conv-100
    Note over Server1: sessionId 생성 (sse-100)<br/>conversationId 바인딩 (conv-100)
    Server1->>RedisReg: SET session:host:sse-100 "node-1" EX 3600
    Server1-->>Client: event: INIT (sessionId: "sse-100", conversationId: "conv-100")

    %% 2. L4 Round-Robin POST Request
    Client->>Server2: POST /api/chat/message (conversationId: "conv-100", sessionId: "sse-100", query: "LiteLLM")
    Server2-->>Client: 202 Accepted
    Server2->>Kafka: Produce to 'agent-requests' (hostId 미고정 발송)

    %% 3. Python Worker Processing
    Kafka->>Agent: Consume request
    Agent->>Kafka: Produce response to 'agent-responses'

    %% 4. Consumer Dynamic Lookup & Redis Streams Relay
    Kafka->>Server2: Consume response (type: CHUNK / STATUS / A2UI)
    Server2->>RedisReg: GET session:host:sse-100 동적 조회
    RedisReg-->>Server2: "node-1" (Node 1에 소켓 존재 확인!)
    Server2->>RStream: XADD stream:bucket:07 (targetHost: node-1, event: CHUNK)

    %% 5. Node 1 Stream Read & Client SSE Delivery
    RStream->>Server1: XREAD stream:bucket:07 (Node 1 버킷 워커 수신)
    Server1-->>Client: event: CHUNK / STATUS / A2UI (SSE 배달)
```

## 4. 핵심 REST API 사양

* **`GET /api/chat/stream?conversationId={id}`**: SSE 스트림 커넥션 수립 (W3C `Last-Event-ID` 수신 시 미열람 토큰 리플레이 스트리밍)
* **`POST /api/chat/message`**: 질의 전송 (`conversationId`, `sessionId`, `query` 발송)
* **`GET /api/chat/conversations`**: 이전 대화 목록 조회
* **`GET /api/chat/conversations/{conversationId}`**: 특정 대화 상세 이력 및 완료 리포트 복원 조회
