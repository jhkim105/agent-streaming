## 1. 아키텍처 개요 및 도메인 모델 분리

본 시스템은 동시 연결 처리가 우수한 **JVM 리액티브 모델(Kotlin WebFlux Agent Stream Server)**과 **파이썬 에이전트 워커(LangGraph Worker)**를 비동기 메시지 브로커(Kafka), 레디스(Redis Pub/Sub) 및 대화 영속성 저장소로 연결한 **이벤트 구동형 대화 아키텍처**입니다.

### 🔑 식별자 역할 분리 (Identity Model)
* **`sessionId` (Stream Connection ID)**: 네트워크 SSE 연결 생명주기를 다루는 소켓 식별자입니다. 새로고침 시 새로 생성됩니다.
* **`conversationId` (Business Conversation ID)**: 리서치 대화 스레드의 생명주기를 다루는 도메인 식별자입니다. 새로고침 시에도 동일한 ID로 대화 및 리포트를 복원하고 이어나갈 수 있습니다.

## 3. 시퀀스 플로우 (Sequence Diagram)

### 3.1. 대화 수립, 질문 전송 및 실시간 이력 저장 플로우

```mermaid
sequenceDiagram
    autonumber
    actor Client as Client (React SPA)
    participant Server1 as Stream Server (node-1)
    participant Kafka as Kafka Broker
    participant Agent as Python Worker (Qwen2.5)
    participant Server2 as Stream Server (node-2)
    participant Redis as Redis Pub/Sub
    participant DB as Conversation History Store

    %% 1. SSE Connection & Conversation Init
    Client->>Server1: GET /api/chat/stream?conversationId=conv-100
    Note over Server1: sessionId 생성 (sse-abc)<br/>conversationId 바인딩 (conv-100)
    Server1-->>Client: event: INIT (sessionId: "sse-abc", conversationId: "conv-100")

    %% 2. Request Dispatch
    Client->>Server1: POST /api/chat/message (conversationId: "conv-100", sessionId: "sse-abc", query: "LiteLLM")
    Server1->>DB: 질문 및 대화 메타데이터 저장 (conv-100)
    Server1-->>Client: 202 Accepted
    Server1->>Kafka: Produce to 'agent-requests'<br/>{conversationId: "conv-100", sessionId: "sse-abc", hostId: "node-1", query: "..."}

    %% 3. Python Agent Execution & Token Streaming
    Kafka->>Agent: Consume request
    loop Worker Reasoning & Ollama LLM Streaming
        Agent->>Kafka: Produce (type: STATUS / CHUNK / A2UI / DONE)
        Kafka->>Server2: Consume response (Target hostId: "node-1")
        Note over Server2: hostId 불일치 감지 (node-2 ≠ node-1)
        Server2->>Redis: Publish to 'host:node-1'
        Redis->>Server1: Receive event from 'host:node-1'
        Server1->>DB: 대화 이벤트 및 완성 리포트 축적 저장 (conv-100)
        Server1-->>Client: event: CHUNK / STATUS / A2UI / DONE (SSE 배달)
    end
```

### 3.2. 새로고침 시 대화 복원 및 이전 대화 목록/상세 조회 플로우

```mermaid
sequenceDiagram
    autonumber
    actor Client as Client (React SPA)
    participant Server as Stream Server
    participant DB as Conversation History Store

    %% 1. 새로고침 발생 시 대화 복원
    Note over Client: 사용자가 브라우저 새로고침 발생!
    Client->>Server: GET /api/chat/conversations/conv-100 (상세 복원 요청)
    Server->>DB: conversationId('conv-100') 전체 이력 조회
    DB-->>Server: 대화 제목, 타임라인, 완성된 마크다운 리포트, A2UI 반환
    Server-->>Client: 200 OK (이전 대화 화면 완벽 복원)

    %% 2. 이전 대화 목록 조회
    Client->>Server: GET /api/chat/conversations (목록 조회 요청)
    Server->>DB: 전체 대화 스레드 목록 조회
    DB-->>Server: List<ConversationSummaryDto> 반환
    Server-->>Client: 200 OK (사이드바 히스토리 목록 렌더링)
```

## 4. 핵심 데이터 모델 및 API 사양 요약

### 4.1. REST API 사양
* **`GET /api/chat/stream?conversationId={id}`**: SSE 스트림 커넥션 수립 (기존 대화 이어서 스트리밍 가능)
* **`POST /api/chat/message`**: 질의 전송 (`conversationId`, `sessionId`, `query` 실어 발송)
* **`GET /api/chat/conversations`**: 이전 대화 목록 조회
* **`GET /api/chat/conversations/{conversationId}`**: 특정 대화 상세 이력 및 완료 리포트 복원 조회
